# Loopstack 0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a backward-compatible Loopstack 0.3 that executes bounded maker/checker prompt cycles inside typed business workflows across Hermes, Claude Code, and Codex.

**Architecture:** Add typed v3 contracts around the existing loop definition rather than replacing it. Keep state-machine execution, prompt-cycle orchestration, learning governance, storage modeling, and runtime rendering in separate modules connected through explicit interfaces. Preserve all v1/v2 handoffs and normalize legacy 0.2 loops into disabled, safe v3 runtime packages.

**Tech Stack:** TypeScript 7, Zod 4, Vitest 4, YAML, Python Hermes adapter, JSON Schema draft 2020-12

## Global Constraints

- Release version is exactly `0.3.0` in every runtime and marketplace manifest.
- Every valid 0.2 loop definition and every v1/v2 handoff remains readable.
- The canonical cycle is `Target → Observe state → Evaluate/Plan → Act → Observe result → Evaluate outcome → Learn → Decide`.
- No parsing, rendering, build, test, or migration step may enable or execute a trigger.
- Human timeout never auto-approves.
- Model confidence never independently authorizes a consequential action.
- Plugin-provided Hermes skills are read-only learning targets.
- Hermes internal `state.db` is never used as the loop store.
- Every production behavior is introduced through a witnessed RED → GREEN TDD cycle.
